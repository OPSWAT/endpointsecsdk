# Python DLP Scanner — hello world

The simplest possible example of the **OESIS Endpoint-DLP** feature: scan **one
file** for **sensitive data** — Social Security numbers, credit-card numbers,
IBANs, and ~2,000 other detectors.

It calls the DLP engine (`libwadlpscan.dll`) directly through its C ABI with
`ctypes`, so it doubles as a minimal reference for embedding DLP into your own
tooling. The engine is loaded from the `sdk/` subfolder — no configuration.

> Want confidence-floor tuning, folder/batch scanning, text scanning, or raw
> JSON output? Those belong in the more advanced **configuration** sample; this
> one stays deliberately small.

## What it does

Given a file, the engine extracts its text (plain text, PDF, Office documents,
HTML/email, **images via OCR**, archives, …) and runs every detector over it,
printing each detector that fired and its confidence (0–100). Detections below a
fixed confidence floor (80) are dropped so ordinary text (order numbers, build
numbers) isn't flagged.

## Requirements

- **Windows, macOS, or Linux** (x64). The scanner loads the matching engine
  library automatically — `libwadlpscan.dll` / `.dylib` / `.so`.
- **Python 3.8+**
- The **OESIS DLP engine runtime** for your platform, staged into `sdk/` (not
  committed — run `prepare.py`, below). Use the DLP package built for the OS you
  run on. No license file is required for this engine build.
- `Pillow` — only to regenerate the image sample (`pip install pillow`)

## Setup

Run `prepare.py` once. It copies the engine DLLs, the detector rulepack, and the
OCR data into `sdk/` from the OESIS DLP package (`OESIS-DLP-*.zip` or its
unpacked folder). With no argument it uses the newest package in your Downloads
folder:

```bash
python prepare.py                                     # auto-find in ~/Downloads
python prepare.py --source C:\path\to\OESIS-DLP-v3-2026-08-14.zip
python prepare.py --source C:\path\to\OESIS-DLP-Demo   # an unpacked folder
```

It copies only the seven files the DLP scan path needs (the scanner engine, its
two dependency DLLs, `pdfium` for PDFs, the rulepack + its manifest, and the OCR
data) and skips everything else in the package. The staged `sdk/` contents stay
local (they're in `.gitignore`).

The sample documents used in the examples below aren't committed either — create
them once with:

```bash
python make_samples.py
```

## Usage

```bash
python dlp_scan.py <file>
```

Examples:

```bash
python dlp_scan.py samples/sensitive/employee_record.pdf   # PDF text
python dlp_scan.py samples/sensitive/bank_statement.png    # image, via OCR
python dlp_scan.py samples/clean/meeting_notes.txt         # nothing to find
```

Exit codes: `0` = clean, `2` = sensitive data found, `1` = error (so it can gate
a script).

### Example output

```
Scanning: ...\samples\sensitive\employee_record.pdf

RESULT: SENSITIVE DATA FOUND

  - SSN (confidence 90)
  - us-social-security-number (confidence 80)
```

## Sample files

Generated by `make_samples.py` (regenerate any time with
`python make_samples.py`, which needs `Pillow` for the image). The corpus is
split into files that **should** trigger detections and files that should stay
**clean**, across several file types and languages — handy for trying the scanner
one file at a time.

**All values are synthetic**: names are invented, SSNs are fictitious, card
numbers are the card brands' public test values, and IBANs are the published
example IBANs — none of it is real personal data.

## How it works

The DLP engine exposes a tiny JSON-in / JSON-out C ABI, mirroring the main OESIS
API:

```
wa_dlpscan_setup(json_config, &json_out)   # initialize + license
wa_dlpscan_invoke(json_in, &json_out)      # configure / scan
wa_dlpscan_free(json_out)                  # free a returned buffer
wa_dlpscan_teardown()                      # shut down
```

`dlp_scan.py` makes three calls, in order:

1. **setup** — initializes the engine. This engine build needs no license file;
   if a build requires one, a passkey or offline license placed in `sdk/` is
   picked up automatically.
2. **invoke, method `130002`** — loads the detector rulepack (`dlp_rules.dat`)
   and sets the confidence floor. The rulepack's expected SHA-256 (from
   `dlp_rules.manifest.json`) is passed so the engine can verify integrity — a
   mismatch is rejected with `WAAPI_ERROR_HASH_MISMATCH` (-48).
3. **invoke, method `130001`** — scans the file
   (`{"type":"file_path","path":...}`) and returns the detectors that fired.
